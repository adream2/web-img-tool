# 竞品功能梳理与差距分析

> 调研时间：2026-11。对象为可查证的开源项目 / 公开说明的插件，只记录能从其 README、商店页、文档中确认的能力，不做猜测。

## 一、调研对象

| 项目 | 形态 | 许可证/来源 | 值得借鉴的点 |
|---|---|---|---|
| **Image Downloader**（jsxiao fork，源自 PactInteractive） | Chromium 扩展 | 开源（GPL 系） | URL 过滤支持通配符与**正则**；宽/高上下限；「只看链接指向的图」；「只保留唯一图」（同图多尺寸折叠、留最大）；**子目录 + 页面顺序编号**（`img-01`）；筛选状态持久化；列数/显示宽度可调；明暗/跟随系统主题；透明图棋盘格；类型/分辨率/体积徽标；每张图的「打开/下载/复制 URL」三按钮 |
| **Picviewer CE+**（hoothin） | 油猴脚本 | 开源 | 悬停即出浮动工具条与预览窗（翻转/旋转/缩放）；**图库模式**（缩略图侧栏、全屏、幻灯片）；**站点规则系统**（url/src/s 组合、getImage、xhr）适配懒加载与复杂站；ZIP 打包、格式转换、aria2 远程下载；**尺寸滑条 + 默认最小尺寸**；自动收集 `backgroundImage`；「加载更多」聚合下一页；多语言；可导出 PDF 相册（插件） |
| **Image Max URL**（qsniyg） | 扩展 / 脚本 / Node 模块 | Apache-2.0 | **按 URL 规则反推原图**（1 万+ 站点规则 + WordPress/MediaWiki 等通用引擎）；快捷键弹窗画廊；把页面上的图**替换成大图**再配合「下载全部」类扩展；候选 URL 探测后校验可用性 |
| **gallery-dl** | 命令行 | 开源 | **命名模板**（`-f` 格式化串）、**下载归档**（`--download-archive` 增量去重）、按体积/日期过滤的表达式思路 |
| **Grabit** | 扩展（闭源，仅作参照） | — | **自动滚动**触发懒加载后再采集（我们的「深度扫描」已覆盖同类能力） |
| **Fatkun / Imageye** | 扩展（闭源） | — | 尺寸过滤、ZIP、格式转换、按区域选取；Imageye 的 ZIP + 转换是它在评测里的主要加分项 |

## 二、我们的现状与差异化

**已具备（且多数竞品缺失）**

- ZIP 打包下载 —— Image Downloader 明确没有，被用户催了多年
- 下载时格式转换 + 尺寸调整（批量与单张）
- 感知哈希（dHash）**相似图合并** —— 竞品多是按 URL/尺寸去重，不是按画面内容
- GitHub 图床直传（PicX 思路），一键出 Markdown/HTML
- **点图定位到页面元素**（聚光灯高亮）—— 竞品里 `downloadFromElement` 有类似「Locate」，但只是红框，没有面板淡出配合
- 深度扫描（滚动触发懒加载 + CSSOM + Shadow DOM + 同源 iframe + `og:image`）

**已确认的差距**

| # | 功能 | 竞品做得如何 | 我们 | 价值 | 成本 |
|---|---|---|---|---|---|
| 1 | URL 排除 / 正则过滤 | 通配 + 正则 | 已补「排除关键词」，**正则待做** | 高（去掉头像、图标、广告位） | 低 |
| 2 | 仅链接图（缩略图指向的原图） | Image Downloader 有 | 缺 | 高（画廊站核心场景） | 中 |
| 3 | 命名模板 + 子目录 | `img-01` / `{index}` 模板 | 只有净化后的原文件名 | **最高**（电商、自媒体批量归档） | 中 |
| 4 | 记住筛选与排序 | 有 | 缺（重开即重置） | 中 | 低 |
| 5 | 预览键盘导航 / 缩放 | 图库模式支持 | 弹窗无左右键、无缩放 | 中 | 低 |
| 6 | 复制图片本身到剪贴板 | 少数有 | **本轮已补**（预览弹窗「复制图片」） | 高（排版、聊天直接粘） | 低 |
| 7 | 悬停浮动工具条（页面内） | Picviewer / Max URL | 缺 | 中（体验型差异化） | 高 |
| 8 | 按 URL 反推原图 | Max URL 极强 | 缺 | 高但难（需站点规则库） | 很高 |
| 9 | 明暗主题 / 多语言 | 普遍有 | 缺 | 中（商店国际化） | 中 |
| 10 | 下载失败重试 / 失败清单 | 少数有 | 有原因回显，无重试 | 中 | 低 |
| 11 | GIF/APNG 保真 | — | **潜在问题**：批量转格式会走 canvas，动图会掉帧 | 中 | 低 |
| 12 | 跨标签页聚合提取 | Fatkun 有 | 缺 | 中 | 中 |

## 三、路线图建议

**v1.3（低风险，1–2 天，建议上架前或紧随其后）**

1. 命名模板：`{index} {name} {w} {h} {date} {site}`，配「子目录」输入（`chrome.downloads` 的 filename 支持子目录）
2. 记住筛选/排序/尺寸阈值（`chrome.storage.local`）
3. 仅链接图：扫描 `<a href>` 指向图片的地址，类型标记 `link`，筛选里给一个开关
4. GIF/APNG 保真：转换前判断 `image/gif|image/apng`，非明确要求就原样透传
5. 预览键盘 ←/→ 切换、`+/-` 缩放
6. 失败清单 + 一键重试

**v1.4（体验型差异化）**

7. 页面内悬停工具条（`Alt` 呼出，单键下载/复制/放大）
8. 明暗主题 + i18n（英文文案先落地，Edge 商店国际流量）
9. 正则过滤模式（与现在的关键词排除并存，UI 上折叠）

**v2.0（重投入，看用户量再决定）**

10. 通用原图解析：先用「去尺寸后缀 + 去查询参数 + 常见 CDN 规则」的启发式，再逐步积累站点规则
11. 跨标签页聚合（同域名批量扫）
12. 站点规则系统（学习 Picviewer 的 url/src/s 组合）

## 四、明确不做

- **以图搜图**：TinEye/Google 的 API 已收费或限流，Picviewer 也因此废弃了该功能
- **PDF 相册导出**：跟工具定位无关，且会引入大依赖
- **远程下载（aria2/WebDAV）**：需要本地服务端配合，普通用户零收益
- **云端 AI 修图**：涉及上传用户图片，与"全本地处理"的卖点冲突

## 五、可借鉴但不急的实现细节

- 透明图用**棋盘格底**，一眼看出 PNG 是否真透明
- 缩略图徽标同时显示「格式 / 分辨率 / 体积」，比只显示尺寸有用
- 「只保留唯一」默认开启能显著降噪 —— 我们的相似图合并是更彻底的版本，可考虑默认开启（配合「已合并 N 张」提示）
- 下载前提示「未设置默认下载目录时会弹很多另存为窗口」，这是该品类高频投诉
