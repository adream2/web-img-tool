## 二、公众号推文

# 我把"存图"这件事重做了一遍：一个面板收齐整页图片

> 摘要：网页图片一键收齐：按尺寸筛、批量下 ZIP、压缩转格式、相似图自动合并、直传图床。全本地处理，不上传任何数据。顺手聊三个真实痛点和它怎么解的。

写这篇的原因很简单：我每周都要从网页上扒图，用过的插件一只手数不过来，但每次还是要在"漏图、筛不动、下完还要手动改名/转格式"这三件事上耗时间。

所以我干脆自己写了一个，叫 **Web Image Tool Pro**。现在已经能装在 Edge 和 Chrome 上。

## 第一个坑：图列不全

大部分插件只扫 DOM 里的 `<img>`。但真实页面里，图片可能藏在：

- `srcset` 的多倍图里（你看到的 800px，实际有 2400px 版本）
- CSS 的 `background-image`、`mask-image`、`border-image`
- Shadow DOM 和同源 iframe 里
- `og:image` 这种只给分享用的元信息里
- 懒加载属性里（`src` 还是个灰色占位图）

我这个做了三路合并：网络层持续监听图片响应、页面脚本扫 DOM 与样式表、再递归进 iframe 和影子节点。长页面还有「深度扫描」，会自动滚动整页把懒加载都逼出来。

顺带说，开发过程中我发现一个隐蔽的坑：MV3 的 Service Worker 空闲几十秒就会被系统杀掉，之前抓到的图全在内存里，一杀就没。这个问题不解决，用户看到的就是"扫描不全"。现在改成落盘到 `storage.session`，重启还能接上。

## 第二个坑：筛不动

几十上百张图，靠眼睛找是不现实的。

现在可以按尺寸筛（≥100 / 300 / 600 / 宽 1000 / 宽 1920，或者自己填宽高）、按类型筛（图片元素 / 背景图 / SVG / 图标）、按关键词包含和**排除**（比如把 `avatar`、`icon`、`logo` 一次排掉）。

尺寸未知的图会自己探测宽高再参与筛选，不用你一张张点开看。

还有个我挺喜欢的功能：**相似图合并**。同一张图在页面上往往有好几个版本——缩略图、`_800x`、webp 版。它按画面内容比对（不是只看 URL），自动只留最清晰的那张，右下角标个 `+3` 告诉你合并了几张。

## 第三个坑：下完还要收拾

这才是最烦的部分。所以下载这一步我做了三件事：

1. **打包 ZIP**：选 50 张也只生成一个压缩包，文件名自动净化、重名自动加序号。不用在下载文件夹里翻 50 个文件。
2. **下载前就能改**：裁剪、改尺寸（56 种预设，从 16×16 的 favicon 到 1920×600 的 banner）、压缩、JPG/PNG/WebP 互转、放大。全在本地算。
3. **直接到图床**：配好 GitHub 仓库，勾选就能上传，自动生成 Markdown / HTML / CDN 加速链接。

另外两个小细节也顺手做了：

- **点图定位**：列表里点 🎯，页面会滚到那张图并用聚光灯框住，面板自动淡出让你看清。排查"这张到底是页面上的哪张"很有用。
- **复制图片**：预览里直接复制图片本身，粘到微信、文档里就能用，不用先存到桌面。

## 关于隐私

这类工具天然让人警惕，所以写清楚：

- 扫描、处理、压缩、转格式全在你的浏览器里跑，没有服务器
- 没有账号体系、没有统计埋点、没有广告
- 只有你自己配置并主动点击的图床 / AI 接口才会联网，地址是你填的
- 源码公开，可以自己审
